# Which tier each stdlib test belongs to.
#
# A raw pass percentage over the test suite is close to useless as a progress signal. The
# suite is dominated by tests that never touch the operating system, so the number is
# mostly a measure of whether the ABI is right, it moves by a fraction of a percent when
# something real lands, and it says nothing about which part of the port is stuck. Tiers
# replace it. The milestone signal is "tier 1 is green", which is a statement someone can
# act on.
#
# Tier 0 is pure computation. Arithmetic, containers, string handling, compile time
# machinery, the test framework itself. Nothing here asks the kernel for anything, so it
# should pass on Windows for free once the ABI and the calling convention are right. That
# is what makes it the diagnostic: if tier 0 is not green, the problem is not a missing
# Windows implementation of anything, it is the ABI, and no amount of porting library code
# will help.
#
# Tier 1 is the operating system surface this port is actually about. Files, paths, the
# environment, time, threads, the standard streams. This is where the work is.
#
# Tier 2 is what sits on top of a working tier 1 and needs a second system to cooperate:
# loading a shared library by name, hosting CPython, spawning a process.
#
# Tier 3 is deferred. GPU targets, and the POSIX interfaces that have no Windows meaning
# rather than a missing Windows implementation. `pwd` is the clear case: there is no
# passwd database to read, and the answer is not to write one.
#
# Format is a tier number and a Bazel target pattern, whitespace separated. The most
# specific match wins, so a bare label overrides a `/...` pattern that would otherwise
# cover it, and that is how a single file gets pulled out of the tier its directory sits
# in. Read it with scripts/test-tier.sh, which turns a tier into the pattern list to hand
# to Bazel, negations included.
